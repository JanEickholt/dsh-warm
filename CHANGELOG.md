# Changelog

## [0.2.0] - 2026-10-20
### Added
- Stats. dsh-warm now counts what warming bought and what it wasted: per-day and all-time counters for pings (`warms`) and wasted pings by cause (`needless`, `noFollowup`, `expired`), plus `savedCacheTokens` credited from the cache-read tokens of the last successful ping in a necessary, still-held block, and all-time `failed` dispatches. Necessity is judged per block, not per ping: a follow-up past `t0 + TTL` verifiably needed the pings even when each ping is individually bridgeable by its neighbor (the first per-ping marginal rule marked every ping needless on dense grids and never credited a live block — fixed before release). The counters live in `stats.json` (atomic writes, UTC-day buckets) and are served at `GET /api/dsh-warm/stats` as a documented, versioned schema, so third-party consumers such as a dsh-context-insights card can read them without any import in either direction. `expired` counts successful pings whose block lost the cover before the follow-up — their own measured cost rides the token ledger and the follow-up's re-prefill is billed as a normal request outside the stats; `failed` (the ping request itself erroring or aborting) is the separate, all-time provider-side signal.
- Stats toggle: `stats.enabled` (default on). Off means no counting, no `stats.json`, and the route still reports the toggle state.
- Token ledger (schema 2 of the stats route): every counter now also carries a per-model split. Each ping's own cache-read tokens land in `pingCacheReadTokens` under its outcome (`held` = the cost that bought the credited follow-up; `needless`/`noFollowup`/`expired` = cost that bought nothing), its uncached input tokens in flat per-model `pingUncachedTokens` (the raw-price basis — cache misses pay here), and failed pings' observed usage in all-time `failedPingTokens`. Flat fields stay totals across models; dsh-warm ships tokens only and holds no prices. The ping journal gained an additive `uncachedInputTokens` field; lines predating it seed as 0, and an existing `stats.json` boots with its flat counts kept and empty model maps.
- Failed-ping tokens per model (schema 3 of the stats route): failed pings' observed usage is now also tracked per model — `models.<id>.failedPingTokens: { cacheRead, uncached }`, all-time — alongside the flat top-level `failedPingTokens`, which is kept and stays authoritative for pre-upgrade rows (post-upgrade attribution keeps flat equal to the per-model sums). The journal reseed rebuilds the per-model maps per line, so consumers no longer need single-model inference to price failed pings.
- Per-session ledger: the stats route carries a `sessions` map — each bucket shaped exactly like `allTime` (counts + per-model figures; `failed` stays global) so a session view can lead with its own warming story and reuse one pricing formula. Bounded to the 50 most-recently-active sessions (pruned at every write; pruned sessions keep their global numbers), journal-seeded per-session `warms` on a fresh boot, and absent on pre-upgrade `stats.json` files (empty map, flat counts untouched).
- Provider TTL floors in config (`ttlMs` per provider: mistral 302000 measured, openai/anthropic 300000 documented). The stats classification uses them, and load validates them with a warning when the ping grid can never bridge the TTL.
- Expiry-anchored scheduling: with `ttlMs` set, pings fire `ttlMs − marginMs` after the last cache-refreshing event (the captured request, a successful ping's dispatch, or a dry-run preview) instead of on a fixed interval grid — the last safe moment minus a safety buffer, so a block's cover never lapses between grid slots. `marginMs` (default `60000`) is the buffer; a pair with `marginMs >= ttlMs` drops `ttlMs` with a console warn and falls back to the `intervalMs` grid, which stays available for providers without a measured TTL. Failed pings retry after half the margin (at least 1 s), never in a tight loop.
- Empty provider entries adopt the built-in rule instead of silently disabling warming. A `providers` entry left `{}` (or carrying only overrides such as `maxPings`) for a provider dsh-warm ships a measured rule for (mistral/openai/anthropic) resolves to the built-in `intervalMs`/`ttlMs`/`marginMs` with one console warn — previously it failed `intervalMs` validation, warned, and dropped the provider, so a hand-pruned config.json quietly turned warming off. A `ttlMs`-only entry is kept and gets the fallback-grid `intervalMs` defaulted to 240000 (anchored scheduling never reads it); unknown names with neither field still warn + drop. The debug trace follows: the `llm/stream` line's `accepted` flag now means "arm-able capture" (false when the provider is outside the warmed table), and such a capture logs a `drop` event with `reason: 'provider-not-in-table'` right after — never `accepted: true` followed by silence.
- Web client bundle (`dsh.client`, no build step): a "Warm" sidebar-footer row that opens a stats panel, and a `dsh-warm` card on the Plugins page. Both read the stats route; nothing is stored client-side.
- Debug trace: `debug: true` appends every observed event (stream captures, tool windows, ping dispatch/settle, chain partitions with their attribution) to `storages/dsh-warm/debug.jsonl` for live-host diagnosis.

## [0.1.0] - 2026-10-17
### Added
- Initial release: prompt-cache warmer for tool-execution windows. While the agent loop is blocked in a tool, re-dispatches the session's last conversation request through the llm waterfall with `maxTokens: 1` on a per-provider interval (mistral 240 s default from a live TTL probe: 302 s hit / 424 s miss). Idle sessions and user-input tools are never warmed. Journal + daily ping budget at `$DSH_HOME/storages/dsh-warm/`.
